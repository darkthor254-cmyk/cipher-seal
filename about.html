About

What's actually happening

Cipher & Seal encrypts and decrypts entirely inside your browser tab using the Web Crypto API, which is built into every modern browser and never touches a server. There is no backend here, no database, and no account — this site could be hosted anywhere, or opened straight from disk, and encryption would still work.

How the key is derived

Your passphrase is never used directly as an encryption key. Instead, it's stretched through PBKDF2 with SHA-256, 150,000 iterations, and a fresh random 16-byte salt generated for every message. That salt travels along with the cipher text so the receiver's browser can rebuild the same key from the same passphrase — but it makes guessing the key by brute force far slower for an attacker.

Why decryption fails loudly

AES-GCM is an authenticated cipher. Bundled with the cipher text is an authentication tag that only matches if the correct key was used and nothing was altered in transit. Enter the wrong key, or a corrupted cipher text, and decryption stops with "Invalid secret key or corrupted message" — it never silently hands back nonsense.
